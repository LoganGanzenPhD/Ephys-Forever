# Reference test layout

Tests are the ground truth for this project. Fast AI-assisted development is only safe because every analysis is checked against real recordings, known-answer synthetic data, and outputs exported from established software.

## Directory structure

```
tests/
  README.md
  conftest.py                 # shared fixtures, tolerance loader, manifest loader
  tolerances.yaml             # per-measurement numeric tolerances
  data/
    real/                     # real recordings (Git LFS)
      MANIFEST.yaml
      vclamp_epsc_wt_001.abf
      iclamp_steps_001.abf
      ...
    synthetic/                # generated by scripts/make_synthetic.py (do not hand-edit)
      MANIFEST.yaml
      exp_decay_single.atf
      ...
  reference/
    clampfit/                 # outputs exported by hand from the commercial tool
      vclamp_epsc_wt_001/
        settings.yaml         # exactly how the output was produced
        statistics.csv
        fit_results.csv
        events.csv
    synthetic/                # analytic ground truth written by the generator
      exp_decay_single.yaml
  unit/                       # pure function tests, no files, run in seconds
  io/                         # reader tests against real and synthetic files
  analysis/                   # analysis vs. reference comparisons (marker: reference)
  gui/                        # pytest-qt smoke tests
  benchmarks/                 # open/scroll/analysis timing (pytest-benchmark)
```

## Three kinds of truth

| Source | What it proves | Who creates it |
|---|---|---|
| Synthetic data with analytic answers | The algorithm is mathematically correct | `scripts/make_synthetic.py`, deterministic seed |
| Commercial-tool reference exports | Results match what labs currently publish | The maintainer, by hand |
| Real recordings without references | Readers do not crash and metadata parses correctly | The maintainer |

When synthetic truth and a commercial reference disagree, the synthetic result wins for correctness, and the difference is documented in `docs/differences.md` so users understand it.

## Real data manifest (`data/real/MANIFEST.yaml`)

```yaml
- file: vclamp_epsc_wt_001.abf
  format: abf2
  mode: voltage_clamp          # voltage_clamp | current_clamp | gap_free
  protocol: paired_pulse_50ms
  n_sweeps: 20
  n_channels: 2
  channels:
    - {name: IN0, unit: A}
    - {name: IN1, unit: V}
  sample_rate_hz: 20000
  acquired_with: "pClamp 10.7"  # acquisition software and version, if known
  notes: "WT retina, spontaneous EPSCs present between stimuli"
  shareable: true               # false = keep out of the public repo
```

Every file needs `shareable` set explicitly. Unpublished lab data stays in a private test-data repo or local folder and is skipped in public CI when absent.

## Reference export settings (`reference/clampfit/<case>/settings.yaml`)

Record everything needed for someone else to reproduce the export:

```yaml
source_file: vclamp_epsc_wt_001.abf
software_version: "Clampfit 10.7.0.3"
exported_on: 2026-10-24
exported_by: LG
analysis: statistics
sweeps: all
channel: IN0
baseline:
  method: mean
  region_s: [0.000, 0.050]
cursors_s:
  c1: 0.100
  c2: 0.150
filter: none
measurements: [peak, peak_time, mean, area, rise_time_10_90, half_width]
peak_polarity: negative
```

Export results as CSV with one row per sweep and the exact column names from the software, then add a `column_map` in the settings file that maps those names to this project's result field names.

## Synthetic data cases (minimum set for phases 1 to 6)

| Case | Signal | Checks |
|---|---|---|
| `step_known_amplitude` | Square step with known amplitude plus Gaussian noise | Baseline, peak, mean, area |
| `exp_decay_single` | A·exp(-t/τ) + C | 1-term fit recovers A, τ, C |
| `exp_decay_double` | Two exponentials, τ ratio 5 and 20 | 2-term fit, start-value robustness |
| `boltzmann_activation` | G-V curve with known V½ and slope | Boltzmann fit |
| `epsc_train_known_times` | Alpha or biexponential events at known times and amplitudes in noise | Event detection sensitivity and false-positive rate |
| `ap_train` | Spike waveforms with known threshold, peak, width | Spike analysis |
| `line_noise_60hz` | Signal plus 60 Hz and harmonics | Notch filter attenuation |
| `bessel_step_response` | Step through a known filter | Filter cutoff definition |

Each generated file writes its analytic parameters to `reference/synthetic/<case>.yaml`. The generator uses a fixed random seed so output is byte-identical across runs.

## Tolerances (`tolerances.yaml`)

```yaml
default: {rtol: 1.0e-6, atol: 0.0}
io:
  sample_values: {rtol: 0.0, atol: 0.0}       # readers must be exact
measurements:
  vs_synthetic: {rtol: 1.0e-3}
  vs_clampfit:  {rtol: 1.0e-3}
fit:
  tau_vs_synthetic: {rtol: 1.0e-2}
  tau_vs_clampfit:  {rtol: 2.0e-2}
events:
  time_window_s: 0.0005        # a detected event within 0.5 ms of a true event is a hit
  min_recall: 0.95
  max_false_positive_rate: 0.05
```

Tolerances change only by an explicit maintainer decision, recorded in the commit message with the reason.

## Test markers

```
@pytest.mark.reference   # compares to reference/ outputs
@pytest.mark.realdata    # needs files in data/real (skipped if absent)
@pytest.mark.slow        # over ~2 seconds
@pytest.mark.gui         # needs a display or offscreen Qt
```

## Adding a new feature: checklist

1. Add or confirm a synthetic case with analytic truth.
2. Export a matching reference from the commercial tool on at least one real file, with a complete `settings.yaml`.
3. Write the failing tests in `tests/analysis/`.
4. Only then implement the feature.
5. If results differ systematically from the reference, document it in `docs/differences.md` before merging.

## Benchmarks

`tests/benchmarks/` tracks:

- Time to open a large gap-free file (target: under 1 s for 30 min at 20 kHz)
- Time to render one screen of sweeps
- Event detection throughput (samples per second)

Benchmarks run in CI on main only and fail if a result regresses more than 20% from the stored baseline.
